What is Agile? Core concept
The word "agile" means able to move or think quickly and clearly. In software, Agile is a way of planning and doing work where making changes as needed is an important part of the job. Business agility = a company always ready to respond to market changes. All the models below (XP, Scrum, Time Boxing, FDD) are Agile models.
Extreme Programming (XP) — Agile model
What is XP?
Extreme Programming (XP) is one of the most important software development frameworks under Agile. It improves software quality and responsiveness to customer requirements. XP takes the best practices that have worked in the past and pushes them to extreme levels.
Extreme Programming (XP)

5 Core Activities
Coding
Different from traditional coding. Includes drawing diagrams (modeling), scripting web systems, choosing among alternative solutions.
Testing
XP gives the highest importance to testing. It is the primary factor for developing fault-free software. Tests are written before or alongside code.
Listening
Developers must carefully listen to customers. Programmers may not have in-depth knowledge of what needs to be built — listening bridges that gap.
Designing
Good design eliminates complex dependencies. Without proper design, implementation becomes too complex and maintenance becomes expensive.
Feedback
Most important aspect. Frequent contact with the customer makes development effective and ensures the exact customer needs are understood.
Key Principles
Simplicity first
Build a simple system that works now, rather than trying to build something complicated that may never be used.
Focus on immediate needs
Address features that are needed right now; don't spend time and effort on speculations about future requirements.
Quality over speed
XP improves software quality. Taking "best practices to extreme levels" ensures consistent quality through iterations.

Scrum & Sprint — Agile framework
What is Scrum?
Scrum is an Agile development methodology used in software development based on iterative and incremental processes. It is adaptable, fast, flexible and effective. The primary objective: satisfy the customer through transparency in communication, collective responsibility, and continuous progress.
Scrum Framework
Product Backlog
A list of all features, characteristics, requirements, and fixes ordered by priority that the product owner wants. Development begins from a general idea, elaborating this backlog over time.
Sprint Very important
A sprint is a short, fixed time period (2–4 weeks) in which the development team works to complete specific tasks, milestones, or deliverables. Also called "iterations." Sprints break the project into digestible time blocks.
Duration
2 to 4 weeks per sprint. Fixed and cannot be extended once started.
Each sprint delivers
A complete, working result — a variation of the final product that can be delivered to the client with least possible effort.
Sprint is self-contained
Each sprint is an entity in itself. It doesn't depend on another sprint to function — it provides a standalone increment.

Scrum vs XP — Key difference
Both are Agile. Scrum focuses on how to manage the process (sprints, backlog, roles). XP focuses on engineering practices (coding standards, test-driven, pair programming). They can be used together.
Time Boxing & Feature-Driven Development
Time Boxing
Definition
Development is done iteratively (like the Iterative Enhancement Model), but each iteration is done in a "timebox" of fixed duration. The functionality to be developed is adjusted to fit the duration — not the other way around.
Key idea — fixed time, flexible scope
Unlike Scrum where scope is set and time is fixed, Time Boxing strictly fixes the duration and adjusts what gets done within it. If a feature won't fit, it is moved to the next timebox.
3 Fixed Stages per Timebox
Analysis
What needs to be built in this timebox? Requirements gathering and breakdown.
Implementation
Coding and building the features. Teams work in parallel using pipelining.
Deploy
Release the timebox output. Each stage's output becomes the next stage's input.
Pipelining — dedicated teams
There is a dedicated team for each stage so work can be done in pipelining. Stages are chosen so that each performs a logical unit of work that becomes the input for the next stage. This maximises efficiency.
Feature-Driven Development (FDD)
Definition
FDD is an Agile iterative and incremental model that focuses on progressing the features of the software being developed. The main goal: provide timely, updated, working software to the client. Reporting and progress tracking is necessary at all levels.
4 Characteristics Exam favourite
Short iterative
Works in simple and short iterations. Efficiently finishes work on time. Gives good pace for large projects.
Customer focused
Each feature is inspected by the client before it is pushed to the main build/code.
Structured & feature-focused
Initial activities build the domain model and features list. More than 70% of efforts go to the last 2 activities of the lifecycle.
Frequent releases
Continuous release of features. Ensures continuous success of the project.
Advantages
Easy progress tracking Continuous success for large teams Risk reduction via small segments Greater cost estimation accuracy
Disadvantages Common MCQ
Not good for small projects High dependency on lead programmers Lack of documentation

What is Agile? Why is it used? MCQ
Agile is a software development approach where making changes as needed is an important part of the job. It is used because: (1) Requirements change frequently, (2) Customer needs continuous delivery of working software, (3) It allows teams to adapt quickly to new information or market changes. "Agile" means able to move and think quickly and clearly.
List and explain the 5 values of Extreme Programming (XP). Long
  • Communication — Constant interaction between team members and with the customer ensures everyone understands requirements and progress.
  • Simplicity — Build only what is needed right now. Avoid over-engineering and speculating about future requirements.
  • Feedback — Frequent feedback from tests and customers ensures the product meets actual needs and allows fast correction.
  • Courage — Make hard decisions like refactoring code, abandoning a bad design, or telling the customer what they need to hear.
  • Respect — Team members respect each other's contributions and the customer's needs are respected throughout development.
What are the 5 activities in XP? Short
  • Coding — Includes drawing diagrams (modeling), scripting, choosing among alternatives — not just writing code.
  • Testing — Highest importance. Primary factor for fault-free software.
  • Listening — Developers carefully listen to customers to understand system requirements they don't know.
  • Designing — Good design eliminates complex dependencies and makes maintenance affordable.
  • Feedback — Frequent contact with customer makes development effective.
What is Scrum? Explain its key features. Long
Scrum is an Agile development methodology based on iterative and incremental processes. Key features: (1) Adaptable, fast, flexible, effective framework. (2) Uses Product Backlog — a prioritized list of features the product owner wants. (3) Development is done in Sprints — fixed 2-4 week iterations. (4) Each Sprint delivers a complete, working product increment. (5) Primary goal: satisfy customer through transparency, collective responsibility, and continuous progress. (6) After each sprint: Review (demo) and Retrospective (improvements) are held.
What is a Sprint in Scrum? MCQ
A Sprint is a short, fixed time period (usually 2 to 4 weeks) in which the development team works to complete specific tasks, milestones, or deliverables. Sprints are also called "iterations." Each Sprint is an independent entity that provides a complete result — a working version of the product that can be delivered to the client. Sprints break a large project schedule into manageable blocks of time.
What is Time Boxing? How does it differ from Scrum? Short
Time Boxing is an Agile model where each iteration is done within a fixed duration (the timebox). Unlike Scrum where the scope of work is decided first and the sprint accommodates it, in Time Boxing the time is strictly fixed and the scope (functionality) is adjusted to fit within that time. Each timebox has 3 fixed stages: Analysis → Implementation → Deploy. Dedicated teams handle each stage in a pipeline fashion, making it efficient for large parallel teams.
What is FDD? List its characteristics, advantages and disadvantages. Long
FDD (Feature-Driven Development) is an Agile iterative and incremental model focusing on progressing software features. Its goal is to deliver timely, updated, working software to clients.

Characteristics:
  • Short iterative — simple, fast iterations, good pace for large projects
  • Customer focused — each feature inspected by client before merging
  • Structured & feature-focused — domain model built at start, 70%+ effort on last 2 activities
  • Frequent releases — continuous feature releases
Advantages: Easy progress tracking, continuous success for large projects, risk reduction, greater cost estimation accuracy.
Disadvantages: Not suitable for small projects, high dependency on lead programmers/designers/mentors, lack of documentation.

Compare any two Agile life cycle models. Long
Comparing XP and Scrum:
  • Focus: XP focuses on engineering practices and code quality. Scrum focuses on process and team management.
  • Iteration: Both use iterations. Scrum calls them Sprints (2-4 weeks, fixed). XP iterations are also short but focus on coding practices.
  • Values: XP has 5 explicit values: Communication, Simplicity, Feedback, Courage, Respect. Scrum has no explicit values list but relies on transparency, inspection, and adaptation.
  • Customer: XP requires an on-site customer for constant feedback. Scrum uses a Product Owner who sets backlog priorities.
  • Testing: XP gives highest importance to testing (test-first approach). Scrum leaves testing practices to the team.
  • Best use: XP = small teams, high code quality. Scrum = most projects, any size.
Pro tips for Unit 6
1
XP values — memorise with "CSFCR": Communication, Simplicity, Feedback, Courage, Respect. This comes up as MCQ and short answer.
2
Sprint duration is always 2–4 weeks. Never say "1 week" or "1 month" in the exam — that is wrong.
3
FDD is NOT good for small projects — this is a classic MCQ trap. The exam loves asking "which model is not suitable for small projects?" Answer: FDD.
4
Time Boxing = time is fixed, scope is flexible. Scrum = scope is fixed per sprint, time is fixed. These are often confused — know the difference.
5
7 SDLC stages mnemonic: "Research Plans Design Content — Developers Test Daily" (R-P-D-C-D-T-D).
