Unit 1 — Introduction to Mobile Applications
8 hrs · App intro, history, platforms, comparison
📱 Mobile Applications
1.1 Introduction
Computer program/software for mobile devices (phone, tablet, watch). Runs in mobile environment limited by screen, hardware, battery, connectivity.
3 Types of Apps
Native — built for one platform (Android/iOS)
Web Apps — run in browser, HTML/CSS/JS
Hybrid — mix of native + web
1.2 History
Early apps: calculators, ringtones, games. Nokia 6110 (1997) — first "Snake" game app. WAP = stripped-down HTTP for early phones.
Key Milestones
1983 — Motorola DynaTAC 8000X (first cell phone)
1997 — Nokia 6110 "Snake" (first mobile app)
2007 — iPhone released (Apple)
2008 — App Store + Android launch
2011 — 1 million apps, app use > web use
1.3 Distribution Platforms
Google Play
Android, 3.48M+ apps, $25 one-time developer fee
Apple App Store
iOS, opened 2008, secure distribution for iPhones/iPad/iPod
Windows Store
Microsoft, launched 2010, replaced Windows Phone Store in 2015
Google Assistant / Siri
Intelligent Personal Assistants — Speech-based NUI (Natural User Interface)
1.4 Mobile App vs Application Software
Mobile app = designed for mobile OS (Android/iOS), touch UI, small unit. Application software = desktop, keyboard/mouse, larger scope (e.g. MS Word)
Unit 2 — Mobile Operating Systems
12 hrs · Android, iOS, BlackBerry overview
🖥 Mobile OS
2.1 Introduction
OS that helps run other apps on mobile devices. Like PC OS (Linux/Windows) but lightweight. Earlier OS was simple; now complex due to hardware/internet advances.
2.2 Need & Effectiveness
Need
UI/UX, hardware management, app compatibility, security, connectivity, resource management
Effectiveness
Performance, app compatibility, security (updates), user experience, developer support, maintenance
2.3 Types
Android
Linux-based, open source (Apache License)
Developed by Google. First device: 2008
Uses Dalvik VM (DVM) — JVM optimized for mobile
Layers: Linux Kernel → Libraries → Android Runtime → App Framework → Apps
iOS
Developed by Apple. Closed source, proprietary
Built on Darwin (open-source POSIX-UNIX)
4 Layers: Core OS → Core Services → Media → Cocoa Touch
Touch gestures: swipe, tap, tap-hold, pinch
BlackBerry OS
By RIM (Research In Motion). Best for push email
Uses BlackBerry Enterprise Server (BES) for email
Unit 3 — Android
12 hrs · History, versions, architecture, toolkit
🤖 Android
3.1–3.2 Intro & History
Founded 2003 by Andy Rubin, Rich Miner, Nick Sears, Chris White. Acquired by Google for $50M in 2005. Beta v1.0 released November 5, 2007.
Version Names (A→P)
Astro, Blender, Cupcake, Donut, Eclair, Froyo, Gingerbread, Honeycomb, Ice Cream Sandwich, Jelly Bean, KitKat, Lollipop, Marshmallow, Nougat, Oreo, Pie. Android 10+ uses numbers only.
Key Features
Open source, customizable
Connectivity: GSM, CDMA, Bluetooth, Wi-Fi, LTE, NFC
Storage: SQLite (lightweight relational DB)
Multitasking, Multi-language, Multi-touch
GCM — Google Cloud Messaging (push messages)
Android Beam — NFC-based sharing
3.3 Architecture (5 Layers)
1. Linux Kernel (Heart)
Device drivers, power/memory/process management
2. Native Libraries
WebKit (browser), SQLite (DB), FreeType (fonts), Media, OpenGL, libc
3. Android Runtime
Core libraries + DVM (Dalvik Virtual Machine) — runs apps. Less memory, fast performance
4. Application Framework
APIs: UI, telephony, resources, location, Content Providers, Package Managers
5. Applications
Top layer — Home, Contacts, Browser, Games, etc.
3.4 Development Toolkit
Kotlin
Preferred language since 2019. 100% interoperable with Java. Concise, safe.
Android Studio
Official IDE by Google + JetBrains. Features: wireless debug, Compose preview, Logcat, Gradle, Device Profiler
Firebase
Google backend: authentication, database, cloud storage, Crashlytics, ML Kit
Jira
Project management — tracks issues, sprints, agile. Team collaboration tool
Unit 4 — iOS
12 hrs · History, versions, architecture, toolkit
🍎 iOS
4.1–4.2 Intro & History
Developed by Apple Inc. First released June 2007 with original iPhone. Derived from OS X / Darwin. Supports Objective-C, C, C++, Swift. World's 2nd most popular mobile OS (after Android).
iOS Architecture — 4 Layers
Core OS (lowest)
Bluetooth, Security Services, Accelerate Framework, Local Authorization
Core Services
C and Objective-C frameworks: accounts, contacts, networking, data, location, calendar, SQLite, XML
Media Layer
2D/3D graphics, audio, video technologies
Cocoa Touch (top)
UIKit framework — multitasking, touch input, notifications, UI views, device data access
iOS Versions — Key Milestones
iPhone OS 1 (2007)
First release with original iPhone. Multi-touch concept, no App Store
iPhone OS 2 (2008)
First App Store — third-party apps allowed
iOS 4 (2010)
Name changed from "iPhone OS" to "iOS". Multitasking introduced
iOS 7 (2013)
Complete visual redesign (flat UI by Jony Ive)
iOS 11 (2017)
Dropped 32-bit apps. 64-bit only OS
iOS 13 (2019)
Dark Mode, Memoji. iPadOS split off as separate OS
4.4 iOS Development Toolkit
Swift
Released 2014. Memory-safe, type-safe, 2.6× faster than Objective-C. Preferred language.
Objective-C
Original language, based on C. Supports OOP — encapsulation, inheritance, polymorphism
Xcode
Official Apple IDE (since 2003). For macOS, iOS, watchOS, tvOS development. Includes Instruments, SwiftUI Builder, compilers
Unit 5 — Web Applications
10 hrs · Intro, platforms, components, DB connection
🌐 Web Applications
5.1 Introduction
Application stored on remote server, accessed via web browser. Uses server-side scripts (PHP, ASP) + client-side scripts (HTML, JS). Requires authentication. Examples: Google Apps, Amazon, YouTube.
Client-side code
Runs in browser — responds to user input. Languages: HTML, JS, CSS
Server-side code
Runs on server — handles HTTP requests, stores data. Languages: C#, Java, Python, PHP, Ruby
5.2 Platforms / Frameworks
AngularJS
By Google, 2009. JavaScript framework. Implements MVC. Used by Google, Netflix, PayPal.
ReactJS
By Facebook (Meta). Component-based, Virtual DOM, reusable UI. WhatsApp, Instagram use it.
ASP.NET
By Microsoft. ASP = Active Server Pages. Uses C# or VB.NET
Node.js
JavaScript server environment. Open-source, runs on all platforms. Great for video streaming, SPAs.
5.3 Components
Application Server
Exposes business logic, generates dynamic content. Contains Web + EJB containers. Handles servlet, JSP, EJB.
Database Server
Dedicated to storage and retrieval. Holds DBMS + databases. Key component in client/server architecture.
Web Browser
Displays web pages. Translates HTTP into human-readable content. Supports HTML, XML, CSS.
Connecting to DB
PHP mysql_connect(server, user, password)
PHP PDO — new PDO(mysql:host=..., dbname=..., user, pass)
SQL SELECT — SELECT col FROM table WHERE condition
Unit 6 — Web Application Life Cycle Models
10 hrs · SDLC stages, XP, Scrum, Time Boxing, FDD
🔄 Web App Life Cycle
6.1 Web Dev Life Cycle — 7 Stages
1. Research & Analysis
Gather info about client/project. Understand target audience. Surveys, feedback, requirement elicitation
2. Planning
Wireframes, technology stack, software methodology, content structure
3. Designing
UI/UX design. Layout, buttons, menus, color themes, typography, graphics
4. Content Creation
Writing relevant, easy-to-understand content. CTAs, headlines, formatting
5. Development
Frontend + Backend coding. Most time-consuming stage
6. Testing & QA
Unit testing, stress testing, load testing. Check functionality, usability, compatibility, performance
7. Deployment & Maintenance
FTP-based hosting. Continuous feedback. Regular updates and maintenance
6.2 Life Cycle Models
Extreme Programming (XP)
Agile model. Values: Communication, Simplicity, Feedback, Courage, Respect. Activities: Coding, Testing, Listening, Designing, Feedback.
Scrum
Agile, iterative+incremental. Uses Sprints (2-4 weeks each). Product Backlog = priority feature list. Goal: transparency, collective responsibility, continuous progress.
Time Boxing
Each iteration has fixed duration (timebox). Functionality adjusted to fit timebox. Stages: analysis → implementation → deploy. Pipeline approach with dedicated teams per stage.
Feature-Driven Development (FDD)
Agile, iterative. Focuses on progressing features. Short iterations, customer-focused, frequent releases. Good for large projects. NOT good for small projects.
Characteristics: Short iterative, Customer focused, Structured, Frequent releases
Disadvantage: High dependency on lead programmers, lack of documentation

Unit 1 — Mobile App Intro
What is a mobile application? MCQ
A mobile application is a computer program or software designed to run on a mobile device such as phone, tablet, or watch. It performs specific tasks for the user and is generally small with limited functions.
Which was the first mobile app? Who introduced it? MCQ
Nokia 6110's built-in game "Snake" (1997) is considered the first mobile app.
What is WAP? What was its purpose? Short
WAP (Wireless Application Protocol) was a stripped-down version of HTTP designed for early mobile phones. It allowed mobile devices to access the internet despite limited storage, processing power, and bandwidth. Early WAP sites were extensions of popular websites like CNN.com and ESPN.com.
Differentiate between Mobile Application and Application Software. Long
Key differences:
  • Platform: Mobile apps run on iOS/Android; Application software runs on Windows/macOS/Linux
  • Interface: Mobile apps use touch UI with small screens; Application software uses keyboard/mouse with larger screens
  • Distribution: Mobile apps via App Store/Google Play; Application software via websites/CDs
  • Language: Mobile apps use Java, Kotlin, Swift; App software uses C++, C#, Java, Python
  • Resources: Mobile apps limited by CPU/battery; App software uses more powerful hardware
  • Updates: Mobile apps auto-update via store; App software may need manual updates
  • Examples: Mobile: Instagram, WhatsApp; Application: MS Office, Photoshop
List the major mobile app distribution platforms. Short
1. Google Play (Android, 3.48M+ apps, $25 fee) 2. Apple App Store (iOS, opened 2008) 3. Windows Store (Microsoft, launched 2010) 4. Google Assistant/Siri (intelligent personal assistants)
Unit 2 — Mobile Operating Systems
What is a mobile operating system? MCQ
A mobile operating system is a lightweight OS that helps run other application software on mobile devices. It manages hardware, provides user interface, and enables app compatibility — similar to PC operating systems like Windows or Linux.
What is DVM? How is it different from JVM? Short
DVM (Dalvik Virtual Machine) is Android's virtual machine. It is similar to JVM (Java Virtual Machine) but optimized specifically for mobile devices — it consumes less memory and provides fast performance. It uses just-in-time compilation to translate Java byte code into Dalvik dex-code.
Describe the layers of Android architecture. Long
Android architecture has 5 layers (bottom to top):
  • Linux Kernel: Heart of Android. Manages device drivers, power, memory, and processes
  • Native Libraries: C/C++ libraries — WebKit (browser), SQLite (DB), FreeType (fonts), Media, OpenGL
  • Android Runtime: Core libraries + DVM. Responsible for running Android apps
  • Application Framework: APIs for UI, telephony, location, Content Providers, Package Managers
  • Applications: Top layer — all user apps like Home, Contacts, Browser, Games
What are the 4 layers of iOS architecture? Short
iOS has 4 abstraction layers: 1. Core OS (lowest) — Bluetooth, Security, Accelerate framework 2. Core Services — accounts, contacts, networking, location, SQLite 3. Media Layer — 2D/3D graphics, audio, video 4. Cocoa Touch (top) — UIKit, multitasking, touch input, notifications
Unit 3 — Android
When and by whom was Android founded? MCQ
Android was founded in 2003 by Andy Rubin, Rich Miner, Nick Sears, and Chris White. Google acquired it in 2005 for $50 million.
What is Android Studio? List its key features. Short
Android Studio is the official IDE for Android development, created by Google and JetBrains. Features: Wireless Debugging, Compose Preview, Sync with Android SDK, Built-in Gradle system, Logcat for debugging, Device Manager and Profiler.
Why was Kotlin preferred over Java for Android? Short
Google announced Kotlin as Android's preferred language in May 2019. Kotlin improves on Java by: reducing verbose syntax, adding modern features, being 100% interoperable with Java, providing concise and safer code. Old Java code doesn't need to be replaced — both can coexist.
Unit 4 — iOS
When was iOS first released and on which device? MCQ
iOS (then called iPhone OS 1) was first released on June 29, 2007 alongside the original iPhone.
Compare Swift and Objective-C. Short
Swift: Released 2014, modern, type-safe, memory-safe, 2.6× faster than Objective-C, functional programming support, easier to read. Objective-C: Original Apple language based on C, general-purpose OOP, supports encapsulation/inheritance/polymorphism, similar structure to C. Swift is now Apple's preferred language.
Describe the history of iOS versions and their key features. Long
Key iOS version history: iPhone OS 1 (2007) — First release, multi-touch interface, no App Store. iPhone OS 2 (2008) — App Store introduced, third-party apps. iOS 4 (2010) — Name changed to iOS, multitasking added. iOS 5 (2011) — iCloud, Siri. iOS 7 (2013) — Complete redesign (flat UI). iOS 11 (2017) — 64-bit only, dropped 32-bit apps. iOS 13 (2019) — Dark Mode, Memoji, iPadOS split. iOS 14 (2020) — Widgets on homescreen, App Library. iOS 15 (2021) — FaceTime improvements, Focus mode.
Unit 5 — Web Applications
What is a web application? How does it work? Short
A web application is a program stored on a remote server accessed through a web browser. It uses client-side scripts (HTML/JS for browser) + server-side scripts (PHP/Python for server). Client-side responds to user input; server-side handles HTTP requests and data storage.
Differentiate between Web Server and Application Server. Short
Web Server: Handles only HTTP requests/responses. Serves static content — HTML pages, files, images, videos. Application Server: Exposes business logic, generates dynamic content. Contains Web + EJB containers. Handles servlet, JSP, EJB. Makes website content change based on context.
Write PHP code to connect to a MySQL database. Short
Method 1 — mysql_connect: $dh = mysql_connect(servername, username, password); Method 2 — PDO: $dbconn = new PDO("mysql:host=servername;dbname=databasename", username, password); SQL query: SELECT column1, column2 FROM table1 WHERE column2='value';
Unit 6 — Web App Life Cycle Models
What are the 7 stages of web development life cycle? Short
1. Research & Analysis — gather info, understand users 2. Planning — wireframes, technology stack 3. Designing — UI/UX, layout, colors 4. Content Creation — writing, CTAs 5. Development — frontend + backend coding 6. Testing & QA — unit, stress, load testing 7. Deployment & Maintenance — FTP hosting, updates
Explain Scrum methodology. What is a Sprint? Long
Scrum is an Agile development methodology based on iterative and incremental processes. Key aspects: Product Backlog = ordered priority list of features. Sprint = time-boxed iteration of 2-4 weeks where team completes specific tasks. Each sprint delivers a working product increment. Scrum values: transparency, collective responsibility, continuous progress. It is adaptable, fast, flexible, and customer-focused.
Compare XP, Scrum, Time Boxing and FDD. Long
XP (Extreme Programming): Values-based (Communication, Simplicity, Feedback, Courage, Respect). Activities: coding, testing, listening, designing. Best for quality-focused teams. Scrum: Uses Sprints (2-4 weeks), Product Backlog. Iterative, incremental. Focus on delivering value. Time Boxing: Fixed-duration iterations, functionality adjusted to fit. Pipelined dedicated teams per stage. FDD: Feature-focused, iterative. Customer inspection of each feature. Short iterations. Good for large projects, bad for small. Requires lead programmers.
What are the advantages and disadvantages of FDD? Short
Advantages: Easy progress tracking at all levels, continuous success for large projects, risk reduction through smaller segments, better cost estimation. Disadvantages: Not suitable for small projects, high dependency on lead programmers/designers, lack of documentation.

Exam Pro Tips
1
Always remember the Android architecture layers in order: Linux Kernel → Native Libraries → Android Runtime → App Framework → Applications. A common trick: "Let None Allow Failure Again" (L-N-A-F-A).
2
For iOS, remember 4 layers: "Core OS, Core Services, Media, Cocoa Touch" — bottom to top. Cocoa Touch (UIKit) is always the top layer closest to the user.
3
The 7 SDLC stages for web: "Research Plans Design Content — Developers Test Deployment" (RPDCDTD). Most common long-answer question!
4
For model comparisons (XP vs Scrum vs FDD), focus on the key differentiator: XP = values (5 values), Scrum = Sprints, Time Boxing = fixed duration, FDD = feature focus.
5
Common trap: Don't confuse "Web Server" (static content only) with "Application Server" (business logic, dynamic content). Exam often asks this distinction.
6
Android was acquired by Google in 2005 for $50 million. Beta launched Nov 5, 2007. First phone: T-Mobile G1 / HTC Dream, Oct 2008. Memorize these dates!
7
Swift is 2.6× faster than Objective-C — this specific fact is very likely to appear in MCQ. Also remember: Swift released 2014, Xcode released 2003.
8
For FDD: advantages = reporting at all levels, suits large projects. Disadvantage = NOT good for small projects, lacks documentation, relies on lead programmers. These often appear as MCQs.
9
WAP = Wireless Application Protocol = stripped-down HTTP. This is a very common one-liner MCQ answer.
10
Remember GCM (Google Cloud Messaging) and Android Beam (NFC-based) as unique Android features — they often appear as MCQ options.
